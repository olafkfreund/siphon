# Intent: ops basics (backup and restore, metrics, retention)

## Problem

Siphon is meant to run unattended. An operator still can't safely back it up, watch it, or decide how long it keeps history.

- **No supported backup.** Everything a user built in the portal or with
  `siphon apply` lives next to `server.db` (the NixOS module puts it in
  `/var/lib/siphon`):
  - `state.db` holds the config overlay and its revisions, jobs, approvals, the audit log and notifications;
  - `secrets/` holds the pasted secret values (`secretsDir`, `internal/web/forms.go:170`);
  - `credentials/` holds the subscription logins.

  `state.db` runs in WAL mode. Copying the file while Siphon runs can produce a
  copy that is torn or missing its latest writes. Copying only `state.db` loses
  every pasted secret. In this session the dev instance was backed up by
  stopping it and copying files by hand. Nothing documents any of this.
- **No restore story.** After a lost disk or a bad upgrade, the user has to
  know which files to put back, with which owner and mode. The overlay's
  revision history (`siphon restore <rev>`) only covers config, and only
  while the database survives.
- **Nothing to monitor.** `/healthz` returns `ok` while the process is
  up. Nothing outside the portal shows:
  - the queue depth;
  - jobs failing;
  - approvals waiting;
  - sources that keep failing;
  - notifications that can't be delivered;
  - the daily agent cap being hit.

  #36 tells a person about single events. Nothing gives an existing
  Prometheus/Grafana setup the numbers to alert on and graph.
- **Retention is hard-coded.** Finished jobs and audit rows are deleted
  after 30 days, and seen-event ids after 7 (`internal/store/store.go:283`).
  Some users must keep audit history longer, and a busy instance may want
  less. Neither is possible today.

## Proposed outcome

- **One backup command.** `siphon backup <file>` writes a consistent
  snapshot while Siphon keeps running: the database, `secrets/` and
  `credentials/`, in one archive that only the owner can read. It works
  from a timer (systemd, cron) without a TTY.
- **One restore command.** `siphon restore-backup <file>`, run with Siphon
  stopped, puts the state back. Siphon then starts with every task,
  secret, login and its history as they were. A restore that would
  overwrite existing state asks first, or needs `--yes`.
- **Metrics.** A Prometheus endpoint shows:
  - jobs by state;
  - queue depth;
  - pending approvals;
  - failures;
  - source health;
  - the notification outbox;
  - the daily agent count.

  Each one is a number an operator can alert on, with no per-event labels
  that grow without bound.
- **Retention in `siphon.yaml`.** How long finished jobs, the audit log and
  seen-event ids are kept, with today's 30/30/7 days as the defaults.
- **NixOS.** The module can turn on a daily backup timer. That keeps a few
  archives, so "back it up" is one option.
- **Documented.** A `docs/tasks/` how-to covers backup, restore, moving to a new
  host, and the metrics with example alerts.

## Affected users and systems

- **Operators:** anyone running Siphon (NixOS module, microVM, OCI image).
- **Code:**
  - `cmd/siphon`: the new commands;
  - `internal/store`: the snapshot, retention and metric queries;
  - `internal/web`: the metrics route;
  - `internal/config`: the retention and metrics settings;
  - `nix/module.nix`: the backup timer;
  - the VM test and the docs.
- **No production host changes.** Hosts adopt it by upgrading.

## Constraints

- **Secrets stay protected.** The archive contains secrets, so:
  - it is created `0600` and never world-readable, even for a moment;
  - its contents never appear in logs or command output;
  - the docs say to treat it like the secrets themselves.
- **Metrics never expose content.** No secret, prompt, event body, URL or
  token in a metric name or label. Rule, source and channel names are the
  only labels, and they're already operator-chosen identifiers.
- **Metrics are not open by default.** Either the metrics endpoint needs a
  login, or it is off until the operator turns it on.
- **Restore is offline.** It refuses to run while Siphon holds the
  database lock (`state.db.lock`), so a live daemon never has its files
  swapped underneath it.
- **Retention is operator-only.** Retention lives in `siphon.yaml`, not the
  overlay, like the other `server.*`/`limits` settings. A minimum stops
  `0` from deleting everything, and an audit floor applies.
- **Stdlib first.** No Prometheus client library unless the text format
  turns out to be more than a few lines. Snapshots use SQLite's own
  `VACUUM INTO`, not a file copy.
- **Compatible.** Existing configs and databases keep working. No
  migration is needed unless the spec finds one.

## Open questions

1. **Metrics access.** There are two options:
   - **(a)** `GET /metrics` on the main listener, behind the existing login
     token (Prometheus sends it as a bearer token);
   - **(b)** a separate `server.metrics.listen` address with no auth, off by
     default, usually bound to localhost.

   Recommendation: (a). It needs no new port or exposure, and
   Prometheus supports bearer tokens natively.
2. **Archive encryption.** Should the archive be encrypted (age) or plain
   `0600` tar.gz? Recommendation: plain. Encryption adds a key to manage
   and lose. Users already pipe backups into restic, borg or age, and the
   docs show how.
3. **What the backup includes.** The archive could also include
   `siphon.yaml` and `server.token`. Recommendation: no. Those
   belong to the operator's own config management (Nix, /etc), and the
   archive is only Siphon's runtime state. The restore docs say so.
4. **Backup while running vs. through the API.** `siphon backup` can read the
   files directly (same host, same user as the daemon), or call an API
   endpoint that streams the archive. Recommendation: run it locally only. An
   HTTP endpoint that hands out every secret is a target we don't need.
5. **The NixOS timer default.** Should the timer be off by default, with
   `services.siphon.backup.enable`? Or on, keeping 7 dailies?
   Recommendation: off by default, one option to enable.

## Resolved (owner approval, 2026-10-08)

All five recommendations accepted: (1) `/metrics` behind the login token;
(2) plain `0600` archive; (3) `siphon.yaml` and `server.token` not included;
(4) backup runs locally only, no HTTP endpoint; (5) NixOS timer off by
default.
