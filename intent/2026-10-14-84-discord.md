# Intent: Discord slash commands and interactions trigger rules

## Problem

Discord is "Not yet" in the catalog. A Discord app can send its
*interactions* (slash commands, buttons, modals) to an HTTPS endpoint, the
"Interactions Endpoint URL". Siphon can't be that endpoint today, for two
reasons:

1. **Signatures are ed25519, not HMAC.**
   - Every request carries `X-Signature-Ed25519` (hex) and
     `X-Signature-Timestamp`, signed over `timestamp + body` with the app's
     private key.
   - The endpoint verifies them with the app's **public** key.
   - Siphon only has HMAC and token modes.
   - Discord also deliberately sends badly signed requests while you save
     the URL, and refuses the URL unless they get 401.
2. **Discord needs an answer in the HTTP response, within 3 seconds.**
   - A `PING` (`type: 1`) must get `{"type": 1}`, or the URL can't be
     saved.
   - A slash command must get an interaction response. Otherwise the user
     sees "The application did not respond".
   - Siphon answers `202` with no body.

Channel messages need a gateway bot connection, which is a different
model. That's out of scope here, as the catalog note already says.

## Proposed outcome

- **A webhook signature mode, `ed25519`.**
  - It verifies `X-Signature-Ed25519` over `X-Signature-Timestamp` + body,
    using a hex public key that is configured as the source's secret.
  - The timestamp must be within 5 minutes.
  - It's stdlib `crypto/ed25519`, with no new dependency.
- **A `discord` format on that mode:**
  - it answers `PING` with `{"type":1}`, without delivering it;
  - it answers every other interaction straight away, and delivers it as
    an event;
  - the replay key is the interaction `id`.
- **A `discord` catalog entry:** paste the app's public key, and point the
  Interactions Endpoint URL at the hook.
- **A template:** `/ask` defers, runs an agent, and posts the answer as the
  follow-up message through Discord's interaction webhook. That uses the
  short-lived interaction token in the event, so no bot token is stored.

## Affected users and systems

- Discord app owners.
- `internal/source/webhook.go` (the mode and the format), `internal/config`,
  the catalog, the docs and templates.

## Constraints

- **Constant-time code isn't needed for a public-key check,** but a bad
  signature must still get exactly 401. Discord's URL check depends on it.
- **The public key isn't a secret,** but it's still stored where secrets
  are, so it can't be swapped quietly.
- **The interaction token in the event** is a 15-minute credential for
  that one interaction. It's treated like other event data, and the docs
  say so.
- **No bot token, and no gateway.**

## Open questions

- **The immediate response:** should it be a fixed message (`type: 4` with
  `reply_text`, reusing #82's field), or "thinking…" (`type: 5`,
  deferred), so the real answer can follow?
  - **I'd use deferred by default,** and a fixed message when `reply_text`
    is set. Deferred shows Discord's "thinking" state, and the template's
    follow-up replaces it.
- **The configuration:** a `signature: ed25519` mode plus
  `format: discord`, mirroring #83's `format: eventgrid`? **I'd do that.**
  Other services sign with ed25519 too.

## Decisions (owner, at approval)

- **The immediate response:** deferred (`type: 5`) by default, or a fixed
  message (`type: 4`) when `reply_text` is set.
- **The configuration:** `signature: ed25519` plus `format: discord`.
