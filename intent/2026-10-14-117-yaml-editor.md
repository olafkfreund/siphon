# Intent: editing YAML in the portal feels like a code editor, with live validation

## Problem

Every config editor (rules, sources, agents, routines, …) ends in a plain
`<textarea name="yaml">` (`internal/web/templates/config.html:38-44`):

- **Tab** moves focus out of the box instead of indenting. YAML is
  indentation-sensitive.
- **Enter** loses the current indent.
- **There are no line numbers,** while errors say `yaml: line 8: …`.
- **Validation runs only** when the user presses **Review changes**,
  which re-renders the whole page.

## Proposed outcome

- **The YAML box behaves like a small code editor:**
  - Tab and Shift+Tab indent and outdent the line or selection by 2
    spaces;
  - Enter keeps the indent, and adds 2 after a line ending in `:`;
  - line numbers sit alongside;
  - the line an error names is highlighted.
- **Live validation:** about half a second after typing stops, a status
  line under the box says "Valid · N changes" or shows the error and its
  line. It uses the same dry-run checks as **Review changes**, and doesn't
  save anything.
- **Without JS,** it's the same plain textarea and **Review changes** as
  today.

## Affected users and systems

- Admins who edit config in the portal.
- `internal/web/templates/config.html`, `internal/web/static/app.js`,
  `internal/web/static/style.css`, and `internal/web/configweb.go` (a
  validate endpoint).

## Constraints

- **Strict CSP:** no inline style or script. **No editor library,**
  because CodeMirror 6 injects `<style>`, Monaco is megabytes, and
  CodeJar's `contenteditable` is unreliable. The real `<textarea>` stays
  the form field.
- **Admin only,** like **Review changes**. The validation never writes:
  no commit and no secret files.
- **Reduced motion and contrast** in light and dark.

## Open questions

1. **Syntax colouring?** **Not now.** It needs a mirrored overlay that's
   fragile with wrapping and scrolling. Line numbers, indent help and
   error lines give most of the value. Revisit after use.
2. **Debounce:** 600 ms.
