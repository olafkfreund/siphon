# Intent: Mattermost outgoing webhooks and slash commands trigger rules

## Problem

Mattermost is "Not yet" in the catalog. Its outgoing webhooks and slash
commands don't sign the request. They send a shared **token inside the
body**, as the `token` form or JSON field. Every Siphon webhook mode reads
the secret from a header or a signature, so Siphon can't verify a
Mattermost delivery today.

There's a second gap:
- **Slash commands are always form-encoded,** and outgoing webhooks are by
  default (`application/x-www-form-urlencoded`).
- **Siphon decodes only JSON bodies.** Anything else reaches rules as
  `{"raw": "<body>"}`, so a rule can't match `event.text` or
  `event.user_name`.

## Proposed outcome

- **A new webhook signature mode, `body-token`.** It reads the `token` field
  from a JSON or form body, and compares it in constant time with the
  source's secret.
  - **A wrong or missing token** gets 401.
  - **The token is removed from the event,** so rules, job payloads and the
    portal never see the secret.
- **Form-encoded bodies are decoded into event fields** for every webhook
  source. A single value becomes a string, and a repeated key becomes a
  list. This helps Slack slash commands too.
- **A `mattermost` catalog entry:**
  - it creates a `<name>-hooks` source with `signature: body-token`;
  - its setup text explains where to paste the URL, and where Mattermost
    shows the token;
  - since Mattermost generates the token, the user pastes it into Siphon,
    rather than Siphon generating one.
- **A template,** `mattermost-command-agent`: a slash command, such as
  `/ask`, runs an agent and posts the answer to a channel through an
  incoming webhook.

## Affected users and systems

- Mattermost users (self-hosted or cloud).
- `internal/source/webhook.go` (the mode and form decoding),
  `internal/config` (the enum and validation), `internal/catalog`, the
  docs and the templates.

## Constraints

- **Constant-time comparison, and the secret is never logged.** The token
  never reaches event data, headers or job output.
- **Existing JSON sources behave the same.** Form decoding only applies to
  `application/x-www-form-urlencoded` bodies.
- **The replay key** is the body hash without the token, as for the other
  unsigned modes. Mattermost sends no delivery id or timestamp.

## Open questions

- **The slash command reply.** Mattermost shows the slash command's HTTP
  response to the user. Siphon answers `202` with an empty body, so the
  user sees nothing straight away. Should `body-token` sources reply
  `{"text": "…"}` with a short fixed acknowledgement, or stay empty?
  - **I'd return an optional fixed reply,** with a new source field,
    `reply_text`, empty by default. The real answer goes through the
    rule's action.
- **Should the token field name be configurable** (`token_field`, default
  `token`)? **I'd add it.** It's one line, and it covers other services that
  put a token in the body.
