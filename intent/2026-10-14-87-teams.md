# Intent: Microsoft Teams outgoing webhooks trigger rules

## Problem

Microsoft Teams is "Not yet" in the catalog. A Teams **outgoing webhook**
(Team → Apps → Manage → Create an outgoing webhook) sends a message to an
HTTPS URL whenever someone @mentions it in a channel. Siphon can't take it
today, for two reasons:

1. **The signature.**
   - Teams signs the body with HMAC-SHA256, using a key that Teams shows
     *once* as a base64 string.
   - The result arrives as `Authorization: HMAC <base64 signature>`.
   - Siphon's `sha256` mode expects hex, a raw key, and its own header
     format.
2. **The reply.**
   - Teams waits **5 seconds** for an answer, and shows the HTTP response
     to the user as the bot's reply: a JSON message activity,
     `{"type":"message","text":"…"}`.
   - Siphon answers `202` with no body, so Teams shows an error.
   - An agent can't answer in 5 seconds.

The catalog note calls the second point "needs a synchronous reply". In
practice, Mattermost (#82) and Discord (#84) already solved the same
problem:
- answer at once with a short fixed acknowledgement;
- deliver the event;
- post the real answer later through another channel.

For Teams, that other channel is an *incoming* webhook into the same
channel, created with **Workflows** (the replacement for the retired
Office 365 connectors).

## Proposed outcome

- **A webhook signature mode, `teams-hmac`:**
  - it verifies `Authorization: HMAC <sig>`, where `sig` is the base64 of
    HMAC-SHA256(body, base64-decoded secret);
  - the comparison is constant-time;
  - any failure gets 401.
- **A reply:** with `reply_text` set, an accepted delivery gets
  `200 {"type":"message","text": reply_text}`. Without it, Siphon still
  answers `200 {"type":"message","text":""}`, which Teams shows as no
  reply. A `202` with no body would make Teams show an error.
- **Replays:** keyed by the activity `id` in the body. Teams sends no
  timestamp, so the replay store is the only defence.
- **A `teams` catalog entry:** paste the security token Teams shows, and
  set an optional immediate reply.
- **A template:** `@siphon <question>` acknowledges with "Working on it…",
  runs an agent, and posts the answer through a Teams Workflows incoming
  webhook URL.

## Affected users and systems

- Microsoft Teams users.
- `internal/source/webhook.go` (the mode, and the reply shape),
  `internal/config` (`reply_text` allowed for teams), the catalog, docs and
  templates.

## Constraints

- **The secret is the base64 key Teams shows.** It's stored write-only,
  never logged, and never echoed.
- **No bot registration,** no Azure Bot Service, and no Entra app. Those
  belong to a full Teams bot, which is out of scope.
- **Message text is untrusted.** Teams includes the @mention markup in
  `text`, and the template strips the mention before using it.
- **No new dependency.**

## Open questions

- **Is "fixed acknowledgement plus incoming-webhook answer" enough, or is
  a real Teams bot needed?** A bot (Azure Bot Service) can reply in a
  thread and send proactive messages, but needs an Entra app
  registration, a Bot Framework token, and JWT verification of Bot
  Framework requests. **I'd ship the outgoing webhook now.** It works with
  no Azure setup. A bot can be its own issue later.
- **Should `reply_text` be reused?** It's the same field as Mattermost and
  Discord. **I'd reuse it.** Only the JSON shape differs per format.
