# Spec: bring the docs up to date with main

## Design

Fix each finding of the docs review (reproduced in full in the plan) in
place, using the fix text the review gives. The review checked each fix text
against the code and gives file:line for both sides.

- **Wrong (14):** rewrite the sentence so it matches the code:
  - README.md: sessions, polkit, agent kinds, "one YAML file";
  - routine.md and llms.txt: schedules;
  - llm.md and troubleshooting.md: `on: each`;
  - getting-started.md: the `why` sample;
  - concepts.md: cooldown, the API-key row, `new task`.
- **Missing (11):** add short paragraphs or rows where readers already look:
  - routine.md: the editor;
  - concepts.md: YAML editing, the `servicenow` row;
  - notifications.md: recovery;
  - llm.md: the MCP tools;
  - AGENTS.md: commands and layout;
  - the docs/README.md, llms.txt and templates/README.md indexes.

  The portal tour (Missing 11) is a single sentence in concepts.md, not a
  new page.
- **Stale (6):**
  - "~30 templates" → "about 50" in all five places;
  - the README webhook-auth table → a link to the full list in
    webhook-command.md, not a copy;
  - "presets" → a list naming the catalog, pointing to `siphon catalog`;
  - llms.txt ServiceNow;
  - the AGENTS.md Stack line → "stdlib first; see go.mod";
  - the `explain` kinds.
- **Minor (6):**
  - the `connect` usage line in `cmd/siphon/cli.go`;
  - three `explain.go` descriptions;
  - the servicenow.md "YAML tab";
  - templates/README.md order;
  - the agy argv note in README;
  - the operator-only list in troubleshooting.md.

Then `go generate ./docs`, because the usage line feeds `docs/cli.md`.

## Alternatives rejected

- **Rewriting the README as a shorter landing page.** Out of scope. The
  owner asked for an update, not a restructure.
- **Copying the ten webhook modes into the README.** That creates a second
  list to keep in sync. A link to the one list is enough.
- **A test that fails when the template count drifts.** "About 50" won't
  drift for a long time, and a test for prose is a maintenance cost.

## Risks

- **A fix text is itself wrong.** Mitigation: the implementer re-checks each
  claim's code reference before editing. The Opus review compares the diff
  with the cited code.
- **The `explain.go` edits change CLI output** that a test may pin. Run
  `go test ./...`.

## Verification

- `go generate ./docs`, then `git diff --exit-code` after a second run.
- `go vet ./... && go test -race ./...`, including docs/templates_test,
  the link checks and the `explain` tests.
- An Opus review of the diff against the plan.
