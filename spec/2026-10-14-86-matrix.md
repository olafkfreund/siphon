# Spec: Matrix room events trigger rules, as an application service

## Design

```mermaid
sequenceDiagram
  participant HS as Homeserver
  participant S as Siphon /hook/<name>/_matrix/app/v1/…
  HS->>S: PUT transactions/{txnId}, Authorization: Bearer <hs_token>
  S->>S: bearer check; one event per events[], keyed by event_id
  S-->>HS: 200 {}
  HS->>S: POST ping (bearer)
  S-->>HS: 200 {}
  HS->>S: GET users/@x or rooms/#y (bearer)
  S-->>HS: 404 {"errcode":"M_NOT_FOUND"}
```

### Config (`internal/config/config.go`)

- **The webhook `format`** gains `matrix`. It needs `signature: token` with
  `token_header: Authorization`. The header value is compared as
  `Bearer <secret>`.
- **A new boolean, `allow_query_token`** (matrix only, default false).
  With it, `?access_token=<secret>` is also accepted, for old homeservers.
- **`id`** isn't allowed with `matrix`, because each event carries its own
  `event_id`.
- The schema and `explain` are updated.

### Routing (`internal/web/web.go:172-181`)

Add `PUT /hook/{source}/_matrix/app/v1/{rest...}` plus the same path for
`POST` and `GET`, all to the same `hook` handler. The handler 404s when the
source isn't `format: matrix`. The existing `POST /hook/{source}` stays,
and a matrix source answers it with 404, because the homeserver never uses
it.

### Handler (`internal/source/webhook.go`)

`WebhookOptions` gains `AllowQueryToken`.

**In the `token` case, when `Format == "matrix"`:**
- the expected header value is `"Bearer " + secret`, compared in constant
  time (both hashed, as today);
- if that fails and `AllowQueryToken` is set, compare
  `r.URL.Query().Get("access_token")` with the secret the same way;
- a failure gets `401 {"errcode":"M_FORBIDDEN"}` (the Matrix error shape).
  The `reject` reason is fixed text.

**The headers map** drops `authorization`, as today.

**`serveMatrix`,** after authentication, routes on the path suffix after
`/_matrix/app/v1/`:

| Method + path | Answer |
|---|---|
| `PUT transactions/{txnId}` | Decode `{"events":[…]}` (it must be an array of objects, each with a string `event_id`, or 400 with `M_BAD_JSON`). For each event, run `Limit.Allow` (429 `M_LIMIT_EXCEEDED`), then `deliver` keyed by `event_id`. Answer `200 {}`, or 500 on a delivery error. |
| `POST ping` | `200 {}` |
| `GET users/{id}`, `GET rooms/{alias}` | `404 {"errcode":"M_NOT_FOUND"}` |
| anything else | `404 {"errcode":"M_UNRECOGNIZED"}` |

Every answer has `Content-Type: application/json`, and none echoes request
content.

### Catalog (`internal/catalog/services.yaml`)

`matrix` replaces the not-yet line.

- **Fields:**
  - `name`;
  - `homeserver_name` (text, required, for example `example.org`, used
    in the namespace regexes);
  - `rooms` (text, default `.*`, a regex of room aliases to receive);
  - `localpart` (default `siphon`).
- **Creates `{{.name}}-hooks`:**
  - `hook: true`;
  - `type: webhook`, `signature: token`, `token_header: Authorization`,
    `format: matrix`;
  - `secret: {{generated "hs_token"}}`.
- **The registration YAML,** shown once in the Done result. It's a Done
  field (`Registration`) if `setup` can't render generated values. Check
  `render.go` first.

  ```yaml
  id: siphon-<name>
  url: <hook URL without a trailing path>
  as_token: <generated, shown once, not stored: Siphon doesn't use it yet>
  hs_token: <the generated hs_token>
  sender_localpart: <localpart>
  rate_limited: false
  namespaces:
    users: []
    aliases: [{exclusive: false, regex: "#<rooms>:<homeserver_name>"}]
    rooms: []
  ```

- **Setup text:** save that as `siphon.yaml` on the homeserver, add it to
  `app_service_config_files` (Synapse), and restart. Then invite
  `@<localpart>:<homeserver_name>` to the rooms.

  The homeserver's sender user must be in a room to get its events, unless
  the alias namespace matches it. That's documented.

### Template: `docs/templates/matrix-deploy-command.yaml`

"Notifications & glue":
- the rule `when: 'event.type == "m.room.message" && event.content.body startsWith "!deploy"'`,
  `on: each`, `id: event.event_id`, `cooldown: 1m`;
- the action is a routine stub that echoes the sender and the room.
  Replies are out of scope.

`baseConfig` gets
`matrix-hooks: { type: webhook, signature: token, token_header: Authorization, format: matrix, secret: env:AGW_HOOK }`.

### Docs

The webhook docs line, `docs/llm.md`, and `go generate ./docs`.

## Alternatives rejected

- **Storing `as_token`.** Siphon doesn't use it until replies exist.
  Storing an unused credential is only risk. The admin keeps it in the
  registration file, where the homeserver needs it anyway.
- **A generic `bearer` signature mode.** `token` with
  `token_header: Authorization` and the matrix format already says it. A
  general bearer mode can come when a second service needs one.
- **Accepting `?access_token=` by default.** Tokens in URLs end up in logs.

## Risks

- **The `{rest...}` routes** add PUT and GET under `/hook/`. They reach the
  handler only for existing webhook sources, and only `format: matrix`
  answers. Others get 404, so other sources don't change.
- **Homeservers retry failed transactions with backoff.** A sustained 429
  or 500 delays events. Event-id replay keys make the retries safe.
- **Encrypted rooms:** an AS can't read end-to-end encrypted messages
  without its own crypto. The docs say "unencrypted rooms only".

## Verification

- **`internal/source` tests:**
  - a transaction of 2 events, with the bearer, gets 200 `{}` and 2
    deliveries keyed by `event_id`;
  - re-sending it gets 200 and no new deliveries;
  - no bearer, or a wrong one, gets 401 `M_FORBIDDEN`;
  - a query token is refused by default and accepted with
    `allow_query_token`;
  - ping gets 200 `{}`;
  - a user or room query gets 404 `M_NOT_FOUND`;
  - an unknown path gets 404;
  - bad JSON gets 400;
  - a non-matrix source gets 404 on these paths;
  - the event headers have no `authorization`.
- **`internal/web`:** the new routes reach the handler (PUT, GET, POST).
- **`internal/config`** cases; the catalog render (registration content,
  and the hs_token stored as the secret); `TestTemplatesValidate`; the docs
  tests; `go vet ./... && go test -race ./...`.
- **Manual:** curl a PUT transaction, a ping and a user query at a
  throwaway Siphon.
