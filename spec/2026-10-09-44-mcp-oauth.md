# Spec: OAuth login for MCP sources

## Design

### Config

`internal/config/config.go:261`:

```go
type Auth struct {
	Bearer Secret `yaml:"bearer"`
	OAuth  *OAuth `yaml:"oauth"`
}

// OAuth logs in to the source's MCP server with the MCP authorization flow.
type OAuth struct {
	ClientID     string   `yaml:"client_id"`     // pre-registered client; empty = dynamic registration
	ClientSecret Secret   `yaml:"client_secret"` // env:/file: ref, only with client_id
	Scopes       []string `yaml:"scopes"`        // replaces the discovered scopes
}
```

```yaml
sources:
  linear:
    type: mcp
    url: https://mcp.linear.app/mcp
    auth: { oauth: {} }
    read: { tool: list_my_issues }
    poll: 5m
```

- **Secret refs:** `ClientSecret` joins `secretPtrs()`, so it must be an
  `env:` or `file:` ref and is masked.
- **`Validate` errors:**
  - `auth.oauth` only on `type: mcp` with a `url` (not a `command`);
  - not together with `auth.bearer`, or with an `Authorization` header;
  - `client_secret` needs `client_id`;
  - it needs `server.public_url`. That URL must be https, or http on a
    loopback host (`localhost`, `127.0.0.1`, `::1`), because OAuth 2.1
    allows nothing else as a redirect URI.
- **Schema:** regenerated.
- **Overlay:** sources added through the API or portal can carry
  `auth.oauth`. The client secret goes through the existing `--secret` path.
- **`siphon explain source`:** documents the three fields.

### Storage

- **Where:** one file per source, `credentials/.mcp/<source>/mcp-oauth.json`.
  It's written by `cred.Store{Dir: <credentials>/.mcp}`, which reuses what
  the store already has:
  - the 0700 dir and 0600 files;
  - the flock;
  - atomic writes;
  - compare-and-swap `Save`;
  - the `.prev` copy.
- **Why `.mcp`:** credential names can't start with `.`
  (`cred.go:220`), so no credential can collide with it.
- **Backups:** they already include all of `credentials/` (#38).
- **`fileProvider`:** gains `"mcp-oauth.json": "mcp"`.
- **Contents:**

  ```json
  { "resource": "<source url>", "issuer": "...", "client_id": "...",
    "client_secret": "<only a DCR-issued secret>", "auth_url": "...",
    "token_url": "...", "auth_style": 0, "scopes": ["..."],
    "token": { "access_token": "...", "refresh_token": "...", "expiry": "..." } }
  ```

  A pre-registered secret is never copied in. It stays a ref in the config.
- **Binding:** a stored login is used only while its `resource` equals the
  source's current `url` and its `client_id` equals the configured one (if
  one is set). Change either, and the source needs a new login. A token is
  never sent to another URL.

### The login manager (new package `internal/mcpoauth`)

The daemon has one `Manager`, shared by the poller, the pipeline and the web
server. It holds one token source per source, so polls and agent runs never
race to use a rotating refresh token.

- **`Handler(source) auth.OAuthHandler`**, used by the poller:
  - `TokenSource` returns the stored login's token source, or nil if there
    is no login;
  - `Authorize` (called on a 401, or on a 403 `insufficient_scope`) never
    waits. It returns `ErrLoginRequired`: "source X needs an OAuth login:
    `siphon connect oauth X`, or Log in on the Sources page".

  The poll fails with that error, so the source shows as failing, and #36
  sends its "source failing" notification. Nothing else is needed for that.
- **`Token(ctx, source) (string, error)`**, used for agent runs: a current
  access token, refreshed if needed. Never the refresh token.
- **Refresh:** `oauth2.Config.TokenSource` wrapped in `ReuseTokenSource`.
  After each `Token()`, a changed token is written back with `Save`
  (compare-and-swap). An `invalid_grant` refresh failure clears the
  in-memory login and returns `ErrLoginRequired`.
- **`Start(ctx, source) (authURL string, err error)`** begins a login. It
  runs go-sdk's `auth.AuthorizationCodeHandler` in a goroutine with a
  10-minute deadline:
  1. Connect to the source with that handler. The server answers 401, and
     the handler does discovery, then registration.
  2. **Registration:**
     - with `client_id` set: a pre-registered client;
     - after an earlier dynamic registration on the same issuer: the stored
       client is reused, passed as `PreregisteredClient` with `Issuer` set,
       so re-logins don't pile up registrations;
     - otherwise: dynamic registration with
       `redirect_uris: [<public_url>/oauth/callback]`,
       `grant_types: [authorization_code, refresh_token]` and
       `client_name: Siphon`.
  3. `RequestRefreshToken: true`. `ScopeFilter` returns `scopes` when it's
     set.
  4. The handler's `AuthorizationCodeFetcher` reads `state` from the
     authorization URL and registers a pending login under it. It hands the
     URL back to `Start` and waits for the callback, or for the deadline.

     `Start` returns as soon as the URL is ready, or an error after 30
     seconds. The handler itself does PKCE S256, the `resource` parameter
     (RFC 8707), and the `state` and `iss` (RFC 9207) checks.
  5. `NewTokenSource` hands over the `oauth2.Config` and the token. The
     manager stores them (with `resource`, `issuer` and the client) and
     makes them the source's live login. The next poll uses it.

  Starting a login cancels any pending one for that source.
- **`Complete(state, code, iss, errParam) (source string, err error)`**,
  called by the callback:
  - finds the pending login by `state` and deletes it (single-use);
  - an unknown or expired `state` is an error;
  - an `error=` from the server fails the login.
- **`Status(source)`:** `none`, `pending`, `ok` (with the access-token
  expiry) or `expired`. It never returns a token.
- **`Logout(source)`:** deletes the stored file and the in-memory login.
- **Pending logins live in memory.** A restart drops them, and the person
  starts again.
- **HTTP client:** discovery, registration, token and refresh requests use
  the source's guarded egress client (`internal/source/netguard.go`).
  - It applies the private-address rules: an authorization server on a
    private address needs `server.services.private_endpoints`.
  - It follows no redirects, so an `Authorization` header can never follow
    one.
- **Errors:** token-endpoint errors are reduced to `error` and
  `error_description` before they reach a log, a source error or the API.
  No token appears in any error.

### Wiring

- **Poller** (`internal/source/mcp.go:191-198`): `MCPOptions` gains
  `OAuth auth.OAuthHandler`. When it's set, `transport.OAuthHandler` is set
  and `bearerTransport` isn't used. `cmd/siphon` passes
  `mgr.Handler(name)` for sources with `auth.oauth`.
- **Agent runs** (`internal/job/pipeline.go:448`): for a source with
  `auth.oauth`:
  - `h["Authorization"] = "Bearer " + tok`, from `mgr.Token`;
  - the token is added to that job's mask list;
  - no token means the job fails with the login message.

  `internal/agentloop` needs no change: it already sends the headers it's
  given.
- **Lifetime:** a run that outlives the access token (usually an hour) gets
  401s from then on. See Risks.

### Web, API, CLI

- **`GET /oauth/callback`:** public, like `/hook/`, because the browser
  arrives from the authorization server without the admin token.
  - It calls `Complete` and renders a small CSP-clean page: "Logged in to X.
    You can close this tab." or the error.
  - An unknown `state` counts toward the per-IP failed-auth limiter.
- **Admin token required:**
  - `POST /api/sources/{name}/oauth/login` returns `{"url": …}`;
  - `GET /api/sources/{name}/oauth` returns `{"status", "expiry"}`;
  - `DELETE /api/sources/{name}/oauth` logs out.

  Each writes an audit row (source name and action, never a value).
- **Portal (Sources page):** an OAuth source shows its status, plus a
  "Log in" (or "Log in again") button. The button is a CSRF-protected form
  POST that answers with a 303 to the authorization URL.
- **CLI:** `siphon connect oauth <source>`:
  - prints the URL;
  - polls the status every 2 seconds until `ok`, an error, or 10 minutes;
  - exits 0 on `ok`.

  `--no-wait` prints and exits; `--logout` logs out. Under `connect`,
  because `connect login` already means model logins (`guided.go:168`).

## Alternatives rejected

- **`siphon connect login <source>`** (the intent's wording). It collides
  with the existing `connect login <provider>` for model logins. This is the
  only change from the intent's outcome.
- **go-sdk's `AuthorizationCodeHandler` in steady state.** Its `Authorize`
  would start a browser flow inside a poll. Our handler fails fast instead,
  and the SDK handler runs only for an explicit login.
- **A new top-level `oauth/` state dir.** Backups and the NixOS module would
  need changes. Under `credentials/`, both are free.
- **Persisting pending logins.** That's more state for a 10-minute window.
  Starting again after a restart is enough.
- **Refreshing tokens on a timer.** Refreshing on use is enough, and a
  timer adds a goroutine per source.
- **A stub OAuth server in the VM test.** The protocol is covered in Go
  against `httptest` servers: go-sdk's `auth.RequireBearerToken` on the MCP
  side and a minimal authorization server. The VM test covers what only
  systemd can show (below).

## Risks

- **Long agent runs.** A run longer than the access-token lifetime loses its
  MCP tools partway. This is accepted and documented. The fix, if needed, is
  a per-run local MCP bridge that refreshes, which is out of scope.
- **Restoring an old backup.** If the server rotates refresh tokens, the
  restored one may already be spent. The source then fails with "log in
  again", which is loud, not silent.
- **Authorization servers that refuse the redirect URI.** Some allow only
  https, or only pre-registered URIs. The person sees the server's error on
  the callback page, and the how-to points at `client_id`.
- **The public callback.** An attacker could guess `state`. It's 130
  random bits, single-use and 10 minutes long, and failures count toward
  the failed-auth limit. A login started by an admin can only complete into
  that admin's pending slot.
- **No host is changed.** NixOS users need `server.public_url` set to a URL
  their browser can reach. That's a config change on their side, which the
  how-to describes.

## Verification

- **Unit tests:**
  - `internal/config`: each `Validate` error above, and `client_secret`
    reaching `Secrets()`.
  - `internal/mcpoauth`, against `httptest` with a minimal authorization
    server and an MCP server behind `auth.RequireBearerToken`:
    - the full login with dynamic registration;
    - the login with a pre-registered client;
    - re-login reuses the stored DCR client (there's one `/register`
      call);
    - a stored login survives a new `Manager` (a restart);
    - refresh writes back the new token;
    - `invalid_grant` leads to `ErrLoginRequired`;
    - a changed `url` invalidates the login;
    - `state` is single-use and expires (injected clock);
    - an `iss` mismatch fails;
    - the file is 0600 in a 0700 dir;
    - no token in any error string.
  - `internal/source`: a poll with no login fails fast with the login
    message (no hang); with a login, it polls.
  - `internal/job`: an agent run gets `Authorization`, never the refresh
    token, and the job output masks the access token.
  - `internal/web`:
    - the login API needs the admin token;
    - the callback is public, single-use, and an unknown `state` counts
      toward the limiter;
    - `TestTemplatesAreCSPClean` passes.
  - `cmd/siphon`: `connect oauth` prints the URL, waits, and exits 0 on
    `ok`.
- **VM test** (`nix/vm-test.nix`): an `auth.oauth` source against a local
  URL shows the login error, without hanging. `POST …/oauth/login` without
  a token returns 401. `/oauth/callback?state=bogus` returns 400.
- **Builds:** `go vet ./... && go test -race ./...` and `nix flake check`
  pass. The only `go.mod` change is that `golang.org/x/oauth2` loses
  its `// indirect` marker. No module is added, so `vendorHash` should be
  unchanged, which is confirmed with `nix build --rebuild .#siphon.goModules`.
- **Live (owner, after merge):** log in to one hosted MCP server (for
  example Linear) from the portal. Watch it poll, restart the daemon, and
  watch it keep polling.
