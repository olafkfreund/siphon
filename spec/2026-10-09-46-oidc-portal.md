# Spec: portal sign-in with OIDC, and roles

## Design

### Config (`server.oidc`, operator-only like all of `server.*`)

```yaml
server:
  public_url: https://siphon.example.com
  oidc:
    issuer: https://id.example.com/realms/main
    client_id: siphon
    client_secret: file:/run/credentials/siphon.service/oidc-secret   # optional (a public client with PKCE)
    scopes: [openid, email, profile, groups]   # default [openid, email, profile]
    groups_claim: groups                       # default "groups"
    allow_private: true                        # the provider is on a private address
    token_login: true                          # default true; false hides the token form
    roles:
      admin:    { groups: [siphon-admins], emails: [alice@example.com] }
      operator: { groups: [oncall] }
      viewer:   { groups: [engineering] }
```

- **Go types:** `config.OIDC` and `config.RoleMatch{Groups, Emails []string}`
  on `Server`.
- **Secret refs:** `client_secret` joins `secretPtrs()`.
- **`Validate` errors:**
  - `issuer` must be https, or http on loopback;
  - it needs `client_id`, and `server.public_url` (same rule as #44);
  - at least one role must have a group or an email;
  - `scopes` must include `openid`;
  - role names are only `admin`, `operator` or `viewer`.
- **Schema and `siphon explain`:** updated.
- **The redirect URI** to register with the provider is
  `<public_url>/login/oidc/callback`.

### Roles and enforcement (`internal/web`)

- **Ordering:** `type role int` with `viewer < operator < admin`.
- **The `portal` wrapper** (`internal/web/portal.go:229`) reads the role
  from the session and checks it before CSRF and before the handler:
  - **GET:** needs viewer. Every page is readable. No page shows a secret
    value today, and that doesn't change.
  - **POST:** needs admin by default, so a new route is admin-only unless
    marked otherwise.
  - **Operator POSTs** are registered through `s.portalAs(roleOperator, h)`:
    - `POST /approvals/{id}/{verb}`
    - `POST /rules/{name}/{verb}` (enable/disable)
    - `POST /rules/test`
    - `POST /agents/egress-preview`
    - `POST /connections/{name}/test`, `POST /services/{name}/test` and
      `POST /services/c/{name}/test`
    - `POST /notifications/{name}/test`
    - `POST /sources/{name}/oauth`
  - **Admin:** everything else: the config editor, logins, notifications
    add/delete, services connect, and model connections.
- **A refused role** gets 403 with "your role (viewer) can't do this; ask an
  admin".
- **Templates:** the layout shows the signed-in name, role and Sign out. A
  `can "operator"` template func hides:
  - approve/deny for viewers;
  - rule toggles for viewers;
  - the config, logins, services and notifications edit controls for
    non-admins.

  The server check is the guarantee. Hiding the controls is only
  convenience.

### Sessions

- **The cookie** stays stateless and HMAC-signed under the per-process key
  (`web.go:201`). It gains who and which role:

  ```
  <ts>|<role>|<base64url(actor)>|HMAC(key, "session:"+ts+"|"+role+"|"+actor)
  ```

- **Lifetime:**
  - **token login:** role admin, actor `portal` (unchanged), TTL 24h;
  - **OIDC:** actor `oidc:<email>` (or `oidc:<sub>` with no verified email),
    TTL 12h.
- **Old cookies:** `sessionValid` accepts only the new format. Old cookies
  stop validating, so people sign in again once after the upgrade.
- **The audit actor:** `s.actor(r)` returns it from the session. It
  replaces the literal `"portal"` actor at the 13 call sites
  (`configweb.go`, `notifyweb.go`, `models.go`, `servicespage.go`,
  `portal.go`, `oauth.go`). Provenance labels (`config.FromPortal`) are a
  separate thing and don't change.
- **Provider tokens** are not kept after sign-in.

### The sign-in flow

1. **`GET /login`:** shows "Sign in with SSO" when `server.oidc` is set,
   and the token form unless `token_login: false`.
2. **`GET /login/oidc`:**
   - makes `state`, `nonce` and a PKCE verifier;
   - stores them in a signed, 10-minute, `HttpOnly`, `SameSite=Lax`,
     `Path=/login/oidc` cookie (`siphon_oidc`, HMAC like the session).
     There's no server-side state;
   - answers 303 to the provider's authorization endpoint with
     `S256 code_challenge`, `state` and `nonce`.
3. **`GET /login/oidc/callback`:**
   - **Rate limit:** `s.lim.blocked(ip)` means 429 first.
   - **Check:** the `state` must equal the cookie's.
   - **Exchange:** the code is exchanged with the verifier through the
     guarded client.
   - **Verify** the ID token with go-oidc's verifier (`ClientID`, issuer,
     `exp`, signature through JWKS). Then check `nonce`.
   - **Read** `email`, `email_verified`, `sub`, `name` and
     `groups_claim`.
   - **Map** the highest matching role. An email matches only when
     `email_verified` is true.
   - **Success:** set the session, clear `siphon_oidc`, audit `oidc_signin`
     (actor and role), and 303 to `/`.
   - **No role:** a 403 page, "Signed in as X, but no Siphon role maps to
     you". Audit `oidc_refused`, with the actor only.
   - **Any failure:** `s.lim.fail(ip)`, and a 400 page with a cleaned
     error. The page never echoes `code`, `state`, a token or a claim
     other than the email.
4. **Discovery:**
   - `oidc.NewProvider` runs lazily at the first `/login/oidc` and is
     cached. A failure is shown on the login page and retried next time.
   - The HTTP client is `source.HTTPClient(allow_private, 30s, 1 MiB)`,
     passed through `oidc.ClientContext`. It follows no redirects and
     applies the private-address rules.
5. **Sign out:** `POST /logout` clears the cookie, as today. Logging out of
   the provider is out of scope.

### Dependency

- **New modules:** `github.com/coreos/go-oidc/v3` and its
  `github.com/go-jose/go-jose/v4`.
- **`vendorHash`:** updated, and confirmed with
  `nix build --rebuild .#siphon.goModules`.

### Unchanged

- **The API and the CLI:** admin token only.
- **`/metrics`:** the scrape token (#40).
- **`/hook/*` and `/oauth/callback`:** behave as today.

### NixOS and docs

- **NixOS:** no module change. The client secret goes through the existing
  `services.siphon.credentials`, as with any other secret.
- **Docs:**
  - **New how-to, `docs/tasks/sso.md`:** register the client, the redirect
    URI, role mapping, examples for Keycloak, Authentik, Google, Entra ID
    and Dex for GitHub, break-glass access, and revocation.
  - **Links and references:** the `docs/README.md` link, the server config
    reference, and `llms-full.txt`.

## Alternatives rejected

- **A server-side session store.** Instant revocation, but a new table and
  lookups on every request. Stateless sessions with a 12-hour cap are
  enough for now. See Risks.
- **Keeping the provider's refresh token to re-check groups.** That's more
  secret state for a small gain.
- **oauth2-proxy in front.** It's another service to run, and Siphon would
  still need roles from headers that it can't verify.
- **Hand-written JWT verification, or `golang-jwt`.** Rejected at the
  intent (question 4).
- **Per-route roles listed in a table.** Defaulting POST to admin is safer:
  a new route can't be forgotten into being open.

## Risks

- **Revocation lag.** Removing someone from a group takes effect when their
  session expires (at most 12 hours), or at a restart, which rotates the
  key. This is documented. An admin who must cut access at once restarts
  Siphon.
- **Lockout.** A wrong mapping or a provider outage locks people out. The
  token login stays as break-glass unless `token_login: false`, and the API
  and CLI keep working either way.
- **Missing group claims.** Some providers don't send groups: Google
  doesn't, and Entra ID drops them past about 200. The docs say to map by
  email, or to configure the provider's group claim.
- **The upgrade.** Old session cookies stop validating, so everyone signs
  in again once.
- **Hosts.** No host is changed. Operators opt in through config.

## Verification

- **Unit tests:**
  - **`internal/config`:** each `Validate` error, and `client_secret` in
    `Secrets()`.
  - **`internal/web`,** against an `httptest` OIDC provider (discovery,
    JWKS with a generated RSA key, authorize, token):
    - the full sign-in maps to each role, and the highest wins;
    - no match means 403 and an `oidc_refused` audit row;
    - `email_verified: false` emails don't match;
    - wrong `state`, wrong `nonce`, wrong `aud`, wrong `iss`, an expired
      token and a bad signature are each refused, and each counts toward
      the limiter;
    - the 10-minute cookie expires (injected clock);
    - a viewer gets 403 on an admin POST and on an operator POST; an
      operator can approve but not edit config; an admin can do both;
    - a tampered session role fails the HMAC;
    - audit rows carry `oidc:<email>`;
    - `token_login: false` hides the form and refuses `POST /login`;
    - `TestTemplatesAreCSPClean` passes.
  - **A route-coverage test:** every registered portal POST either needs
    admin, or is on the operator list. A new route that isn't classified
    fails the test.
- **VM test:**
  - `server.oidc` points at an unreachable issuer, with
    `token_login: true`;
  - the login page shows the SSO button;
  - `GET /login/oidc` reports the discovery failure, without hanging;
  - `GET /login/oidc/callback?state=x` returns 400;
  - the token login still works.
- **Builds:** `go vet ./... && go test -race ./...`,
  `nix build --rebuild .#siphon.goModules`, then `nix flake check`.
- **Live (owner, after merge):** sign in through the owner's provider as an
  admin and as a viewer.
