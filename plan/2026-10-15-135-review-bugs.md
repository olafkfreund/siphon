## Confirmed and partly confirmed: cause, fix and failing test

**C1: unmasked rule errors in logs** (agy 8's schedule log line merges into this one)
- **Cause:** `ruleErr` goes into `slog.Warn` without the masking that `PutRuleError` applies.
- **Fix:** log `pollErrText(cfg, ruleErr)` at `hooks.go:137`, `schedule.go:158` and `pipeline.go:585`. That helper already masks secrets, strips quoted values and caps the length. The webhook path needs `cfg := p.Config()` taken once and passed to both `handleEvent` and the log call.
- **Extra gap:** `stripQuoted` misses unquoted values such as `int(SECRET-abc)`, so the stored copy also keeps the event value (only `cfg.Secrets()` is masked). That needs a separate decision.
- **Test:** send a webhook through a rule `int(event.token) > 0` with `token: "tok-secret-123"` (a value in `cfg.Secrets()`), capture `slog` into a buffer, and assert the token is absent.

**C2: unit outlives its job**
- **Cause:** at `template.go:191` the stop error is discarded, and the function returns `-1, nil` after `os.RemoveAll(runDir)`.
- **Fix:** if `stopUnits` fails, return `fmt.Errorf("unit %s may still be running: %w", unit, err)`, so the job output says so.
- **Test:** stub `stopUnits` to return an error and `startUnit` to block until `ctx` ends, run with a short timeout, and assert a non-nil error.

**C3: secret publish after commit**
- **Fix:** I would leave the order as it is. At most, add a `notice`, as the apply failure does, telling the admin to re-enter the secret.
- **Test:** make the target path a directory so the rename fails, then assert the notice or error.

**C4: transport per poll**
- **Fix:** in `guardedClient`, set `IdleConnTimeout: 90 * time.Second` on the transport. That one line covers HTTP, MCP and ServiceNow. For prompt release, also add a `CloseIdleConnections()` method on `limitedTransport` that forwards to its base, and `defer client.CloseIdleConnections()` in `HTTP.Poll`.
- **Test:** the scratch test, asserting at most 1 open server connection after 50 polls.

**A1: removed MCP source**
- **Cause:** the agent definition is snapshotted, but MCP sources are read live (as the comment at `pipeline.go:129-131` intends). Nothing checks for nil.
- **Fix:** at `pipeline.go:462`, add `if s == nil { return "failed", -1, "mcp source " + name + " no longer exists", nil }`. Routine steps use the same `agentExec`, so they are covered.
- **Test:** `TestZZRemovedMCPSourcePanics`, already in the scratch copy, panics today.

**A2: Review then Confirm drops the secret**
- **Cause:** the confirm form re-posts `mode=yaml` with a `file:` ref, but the pasted value only ever existed in `pending`.
- **Fix:** in `cfgPost` (`configweb.go:361`), when `len(pending) > 0`, show the diff with `v.Done = false` (no Confirm button) and add a note: "Secrets are not kept by Review: enter them again and use Save & apply."
- **Test:** `TestZZConfirmDropsSecret`: assert that no `name="yaml"` confirm form is rendered when a secret is pending.

**A3: `removeLogin`**
- **Fix:** replace line 610 with `os.Remove(filepath.Join(secretsDir(cfg.Server.DB), config.SecretFileName("credentials", name, "api_key")))`, keeping the legacy name as a second `Remove`.
- **Part 2:** for subscription logins, deleting the login files while keeping the config is plausibly intended. For a model connection that is file-defined or overridden, Delete does nothing visible. Either hide the button when the item is not `FromPortal`, or use `s.deleteItem`.
- **Test:** `addLogin(..., "apikey", "k")`, then `removeLogin`, then assert `secrets/credentials--n+api_key` is gone.

**A6:** make `NeedsApproval` mirror `StepNeedsApproval`: `if r.Action.Agent != "" { a := c.Agents[r.Action.Agent]; return a == nil || a.Approve == nil || *a.Approve }`. Its doc comment has also drifted above `StepNeedsApproval`.
- **Test:** `(&Config{}).NeedsApproval(Rule{Action: Action{Agent: "x"}})` should be true.

**A7:** change `agent.go:123` to `m["status"] == "ERROR" || m["is_error"] == true`. This is defensive only, since the claude CLI behaviour is unverified.
- **Test:** a fake runner that prints `{"is_error":true,"result":"x"}` and exits 0 should give `Exit == 1`.

**A9:** after `config.Load` at `main.go:569`, call `items, err := dbOverlay(cfg.Server.DB)`, then `cfg, err = tryLoad(*path, items)`. It cannot use `load()` directly because that would reject the extra `-token-stdin` flag.
- **Test:** put a `credentials/x {provider: claude}` overlay item in the DB and run `credentials ls`; the output should list `x`.

**A11:** delete `checkEdit` and call `s.dryRun(&rev, mutate, pending)` instead. This makes the as-you-type `validate` call do a DNS lookup for credential edits (every 400 ms), which is acceptable but worth knowing.
- **Test:** a model credential whose URL resolves to a private address should get 422 on `/check`.

**A13:** optional. Move `SetSourceEvent` after a non-duplicate `handleEvent` (`if !dup`).
- **Test:** deliver id 1, then id 2, then id 1 again; the last event should be id 2.

**A15:** add `case st.ServiceNow != nil: Kind, Target = "servicenow", st.ServiceNow.Op + " " + snTable(st.ServiceNow)` to both switches, reusing the existing `snTable` (`editors.go:194`).
- **Test:** render `/config/routines/x` with a ServiceNow step and expect the text "servicenow".

## Rejected
- **A4:** removing secret files on delete is intentional (`d1a1522`), and restore then fails with a clear error. Design question: should restore warn, or keep the secrets of deleted items?
- **A5:** operator access to the Notion token is tested and documented. Export shows nothing that viewer-readable `/config` pages don't already show, because secret headers must be refs. Docs gap: the role table in `sso.md:16` does not mention Notion acceptance.
- **A8 (stored part):** only DB or transaction errors and Siphon-generated schedule data reach `last_error`.
- **A10:** OAuth state is inside `credentials/`, which the backup already includes.
- **A12:** SQLite returns NULL rather than an error. Tested.
- **A14:** the field is never read, and the claim about `handleEvent` is false.
- **Clock half of A13:** production uses the same `time.Now`, so it is not a production bug.

Not done: no `-race` or `nix flake check` runs. C2, C3, A3, A9, A11 and A15 are verified by trace only. The claude CLI's exit code when `is_error` is true is unknown.
