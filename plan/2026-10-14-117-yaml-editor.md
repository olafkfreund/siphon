# Plan: editing YAML in the portal feels like a code editor, with live validation

## Approved decisions, carried over

- **There's no editor library.** The real `<textarea name="yaml">` stays
  the form field, enhanced in `app.js`.
- **Syntax colouring is deferred.** The validation debounce is 600 ms.
- **`POST /config/{kind}/{name}/validate`:**
  - it uses the same `h(...)` wrapper as `check`, so it's admin only and
    needs CSRF;
  - it shares `check`'s dry run (`itemYAMLFromRequest`, the stale-rev
    check, `prepare`);
  - it returns the `cfgvalid` fragment with status 200: `.yaml-status.ok`
    "Valid · N changes" or `.yaml-status.err` with `data-line`;
  - it never writes.
- **The editor:**
  - Tab and Shift+Tab indent and outdent by 2;
  - Enter keeps the indent, plus 2 after `:`;
  - Escape then Tab leaves the box;
  - a line-number gutter, synced on scroll;
  - the error line is marked from `data-line`.
- **Built on #118 slice 1:** rebase on main after it merges, since both
  touch `app.js` and `style.css`.

## Steps

1. **`internal/web/configweb.go`:**
   - add `"validate"` to the verbs (`:74`);
   - factor the check dry run (`:274-300`) into a helper used by both
     `check` and `validate`;
   - `validate` renders `cfgvalid`, a new `{{define "cfgvalid"}}` in
     `config.html`.
   - **The tests,** following `config_test.go:225`:
     - valid YAML gives "Valid" and no revision change;
     - invalid YAML gives an error with `data-line`;
     - a viewer gets 403;
     - without CSRF it's refused;
     - a secret in the form is not written.

   → verify: `go test -race ./internal/web`.

2. **`templates/config.html` (`:38-44`):**
   - `code-input` and the `hx-*` attributes on the textarea, admin only;
   - the `#yaml-status` `aria-live` line.

   → verify: `go test -race ./internal/web` (including the CSP test).

3. **`static/app.js`:** `initCodeEditors()` per the spec §3.

   → verify: `go test -race ./internal/web`, then step 5 by hand.

   Traps:
   - no inline handlers;
   - bind once per textarea;
   - don't trap focus.

4. **`static/style.css`:** `.code-editor`, `.code-gutter` (`.is-err`),
   `.code-input` and `.yaml-status`.

   → verify: the visual check.

5. **The visual and keyboard check (mine),** on siphon-dev:
   - edit a rule as YAML;
   - Tab, Shift+Tab, Enter;
   - break the YAML and see the error line; fix it and see "Valid";
   - Escape then Tab;
   - JS off.
