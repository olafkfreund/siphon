# Plan: editing YAML in the portal feels like a code editor, with live validation

## Approved decisions, carried over

- **There's no editor library.** The real `<textarea name="yaml">` stays
  the form field, enhanced in `app.js`.
- **Syntax colouring is deferred.** The validation debounce is 600 ms.
- **`POST /config/{kind}/{name}/validate`:**
  - it uses the same `h(...)` wrapper as `check`, so it's admin only and
    needs CSRF;
  - it shares `check`'s dry run (`itemYAMLFromRequest`, the stale-rev
    check, `prepare`);
  - it returns the `cfgvalid` fragment with status 200: `.yaml-status.ok`
    "Valid · N changes" or `.yaml-status.err` with `data-line`;
  - it never writes.
- **The editor:**
  - Tab and Shift+Tab indent and outdent by 2;
  - Enter keeps the indent, plus 2 after `:`;
  - Escape then Tab leaves the box;
  - a line-number gutter, synced on scroll;
  - the error line is marked from `data-line`.
- **Built on #118 slice 1:** rebase on main after it merges, since both
  touch `app.js` and `style.css`.

## Deviations

- **Steps 1–4:**
  - **The fragment** is a `<div>`, not a `<p>`, so it can hold the sprite
    icon. It carries `data-line` only on an error.
  - **Icons:** `i-check` for valid, `i-x` for an error. The coder missed
    `i-x`, and the session added it.
  - **For `validate`,** a bad name or a stale revision also renders as the
    fragment (status 200), so it shows in the status line.
  - **Escape then Tab:** Escape sets a flag that the next Tab honours (it
    leaves the box). Any other key clears the flag.
  - The textarea also gets `spellcheck="false"`.
  - **The viewer case** is covered by adding `validate` to
    `TestPortalPOSTRoles`'s verbs.
  - **The `line N` extraction** is tested on a YAML parse error only.
- **The Opus review:** no HIGH. Four MEDIUM, all fixed.
  1. **`data-line`** is taken only from the item's own YAML syntax error
     (`yaml: line N`), not from errors in re-parsing the merged config,
     whose line numbers aren't the textarea's. There's a test for a type
     error.
  2. **Shift+Tab** works on whole lines wherever the caret is, with no
     `IndexSizeError` at offset 0.
  3. **Undo:** edits go through `execCommand("insertText")`, so they stay
     on the native undo stack, with `setRangeText` as the fallback.
  4. **The Escape hatch:** Shift no longer clears it, so Esc then
     Shift+Tab also leaves. A visible hint, linked by `aria-describedby`,
     announces it.
  - **LOW, fixed:**
    - the global "Updated" announcer skips the status line;
    - `hx-sync="this:replace"`;
    - a failed validate clears the status;
    - Enter during IME composition is left alone;
    - the error-line tint is 12% and bold, for contrast;
    - the gutter has `contain: size`, so the textarea sets the height.
  - **LOW, accepted:**
    - `validate` still runs `s.state()` for `exists`, a few ms per call;
    - the error mark lags edits by up to 600 ms.
