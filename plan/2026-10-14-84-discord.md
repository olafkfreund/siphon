# Plan: Discord slash commands and interactions trigger rules

## Approved decisions

- **The webhook signature `ed25519`:**
  - it verifies `X-Signature-Ed25519` (hex, 64 bytes) over
    `X-Signature-Timestamp` + body;
  - the secret is a hex public key (32 bytes);
  - the timestamp goes through `freshTS` (5 minutes);
  - any failure gets 401 "signature or timestamp invalid";
  - a key that won't decode gets 500 "public key misconfigured", never
    echoing the key;
  - it's stdlib `crypto/ed25519`.
- **Config:**
  - `ed25519` refuses `signature_header`, `timestamp_header`,
    `token_header`, `token_field` and `id`;
  - a secret whose value is known at validation must be 64 hex characters;
  - `format: discord` needs `ed25519`;
  - `reply_text` is allowed with `body-token` or with `format: discord`;
  - generic `ed25519` without the format delivers with a body-hash key and
    answers 202.
- **`format: discord`** (a new `serveDiscord`, after verification):
  - a non-object body, or one with no `type`, gets 400;
  - PING (`type 1`) gets `{"type":1}` and isn't delivered;
  - autocomplete (`type 4`) gets `{"type":8,"data":{"choices":[]}}` and
    isn't delivered;
  - everything else needs a string `id` (else 400). Run `Limit.Allow`
    (429), then `deliver` keyed by `id` (an error gets 500). The response
    is:
    - `{"type":4,"data":{"content":reply_text}}` when set;
    - else `{"type":5}` for types 2 and 5;
    - and `{"type":6}` for type 3.

    A duplicate gets the same response.
- **The catalog's `discord`:**
  - a required `public_key` field matching `^[0-9a-f]{64}$`, and an optional
    `reply`;
  - it creates `<name>-hooks` with `ed25519`, `format: discord` and
    `reply_text` when set.
- **The template `discord-ask-agent`:** an `/ask` rule and a routine (an
  agent, then a curl `PATCH` to
  `https://discord.com/api/v10/webhooks/{{.event.application_id}}/{{.event.token}}/messages/@original`),
  with the `%q` shortcut comment. Templates don't name egress today, so
  none is added.

## Steps

1. **Config** (`internal/config/config.go`, `explain.go`, the schema).
   - **Signature switch** (about `config.go:1500`): add the `ed25519` case.
     It refuses the fields above, and when `s.Secret.Value != ""`, checks
     `^[0-9a-f]{64}$`.
   - **`format`:** `discord` needs `ed25519`. Extend the format switch
     #83 added.
   - **`reply_text`:** relax the check at about `:1540`, so it's allowed
     with `body-token` or `format: discord`. Keep the 500-character rule
     for both.
   - **Explain:** the enum values `ed25519` and `discord`.
   - **Tests** (a table):
     - a valid discord source;
     - discord with `token`;
     - `ed25519` with a non-hex key;
     - `ed25519` with `token_header`;
     - `reply_text` with discord (valid);
     - `reply_text` with `sha256` (invalid).
   - **Verify:** `UPDATE_SCHEMA=1 go test ./internal/config` once, then
     `go test ./internal/config ./cmd/siphon`. Update
     `TestExplainCommand`'s expected enum if it fails, and log it.

2. **Handler** (`internal/source/webhook.go`, a new test file).
   - **The `ed25519` case** in the signature switch (next to `slack`,
     `:152`), per the decisions.
   - **`serveDiscord(w, r, o, now, body, headers, deliver, reject)`,**
     entered when `o.Format == "discord"`, exactly as `serveEventGrid` is
     entered at `:268`. The single `Limit.Allow` is skipped for this
     format, as for eventgrid.
   - **Tests** in `webhook_discord_test.go`, with a key from
     `ed25519.GenerateKey` and a sign helper:
     - PING gets 200 `{"type":1}`, and nothing is delivered;
     - a bad signature, a stale timestamp (6 minutes), a missing header,
       or a signature of the wrong length gets 401;
     - a command (type 2) is delivered keyed by `id`, with response
       `{"type":5}`;
     - a component (type 3) gets `{"type":6}`;
     - a modal (type 5) gets `{"type":5}`;
     - `reply_text` gives `{"type":4,"data":{"content":…}}`;
     - autocomplete gets type 8, and nothing is delivered;
     - a duplicate gets the same 200 and one delivery;
     - a missing `id` gets 400;
     - a bad public key gets 500, and the body doesn't contain the key;
     - generic `ed25519` without the format gets 202 with a delivery;
     - the headers map has no `x-signature-ed25519`.
   - **Verify:** `go test -race ./internal/source ./internal/job ./internal/web`.
   - **Traps:**
     - The response JSON is a fixed shape built with `json.Marshal`.
     - Only `reply_text` (from config) is echoed, never request content.

3. **Catalog, template and docs.**
   - **`services.yaml`:** replace the discord not-yet line with the entry,
     and add `TestDiscordEntry`, which also checks that a bad `public_key`
     is refused.
   - **`docs/templates/discord-ask-agent.yaml`:**
     - the rule `when: 'event.type == 2 && event.data.name == "ask"'`,
       `on: each`, `id: event.id`, `cooldown: 30s`;
     - the agent prompt uses `{{(index .event.data.options 0).value}}`.
       Check that the template renders, and use a simpler form if
       `TestTemplatesValidate` objects.
   - **`baseConfig`:** the `discord-hooks` line.
   - **Docs:** a README row, the entry's `templates:`, the webhook-docs
     signature table row (`ed25519`, `format: discord`), and a line in
     `docs/llm.md`. Then run `go generate ./docs`.
   - **Verify:** `go test ./internal/catalog ./internal/web ./docs ./cmd/siphon`.
   - **Traps:**
     - The curl URL argument starts with literal `https://`.
     - `--data-raw` starts with `{"content":`.
     - No hand-edited generated files.

4. **All checks, and a signed curl (mine).**
   - `go vet ./... && go test -race ./...`.
   - A scratchpad Go program generates a key pair and signs a PING and a
     command. Post them to a throwaway Siphon and expect `{"type":1}`, then
     `{"type":5}` plus a job. A bad signature gets 401.
