# Plan: portal sign-in with OIDC, and roles

Self-contained. The approved spec decisions, carried over:

- **Off by default.** Without `server.oidc` the portal works as today,
  except that old session cookies stop validating once (new format).
- **One provider,** in `server.oidc`: `issuer`, `client_id`, optional
  `client_secret` (an `env:`/`file:` ref, masked), `scopes` (default
  `[openid, email, profile]`), `groups_claim` (default `groups`),
  `allow_private`, `token_login` (default true), and
  `roles.{admin,operator,viewer}.{groups,emails}`.
- **Roles:** viewer < operator < admin. The highest matching role wins. No
  match is refused. An email matches only when `email_verified` is true.
- **Enforcement in the `portal` wrapper:**
  - GET needs viewer;
  - POST needs admin unless registered with `s.portalAs(roleOperator, …)`;
  - a refused role gets 403.
  - The operator list is closed:
    - `/approvals/{id}/{verb}`, `/rules/{name}/{verb}`, `/rules/test`,
      `/agents/egress-preview`;
    - `/connections/{name}/test`, `/services/{name}/test`,
      `/services/c/{name}/test`, `/notifications/{name}/test`;
    - `/sources/{name}/oauth`.
- **Session cookie:** stateless and HMAC-signed under the per-process key:
  `<ts>|<role>|<base64url(actor)>|HMAC(key, "session:"+ts+"|"+role+"|"+actor)`.
  - The token login is admin, actor `portal`, 24h.
  - OIDC is actor `oidc:<email>` (or `oidc:<sub>`), 12h.
  - Old-format cookies are rejected.
  - Provider tokens are never kept.
- **The audit actor** comes from the session through `s.actor(r)`, at
  every literal `"portal"` actor site. Provenance labels (`provLabel`,
  `config.FromPortal`) don't change.
- **The flow:**
  1. `GET /login/oidc` keeps state, nonce and the PKCE verifier in a signed
     10-minute `siphon_oidc` cookie (`HttpOnly`, `SameSite=Lax`,
     `Path=/login/oidc`).
  2. The callback checks the limiter first, then state, does the code
     exchange with the verifier, verifies the ID token with go-oidc, checks
     the nonce, and maps the role.
  3. It audits `oidc_signin` or `oidc_refused`. Every failure calls
     `s.lim.fail`. The page never echoes `code`, `state`, a token or any
     claim except the email.
- **Discovery** is lazy and cached, and runs through
  `oidc.ClientContext(ctx, source.HTTPClient(allow_private, 30s, 1<<20))`,
  which follows no redirects.
- **Dependencies:** `github.com/coreos/go-oidc/v3`, which brings in
  `github.com/go-jose/go-jose/v4`. `vendorHash` is updated and confirmed
  with `--rebuild`.
- **Unchanged:** the API and CLI (admin token only), `/metrics`,
  `/hook/*` and `/oauth/callback`. There's no NixOS module change.

## Decisions the spec left open (settled here)

These need the owner's eye on this plan:

1. **`POST /logout` is viewer-level.** The spec's admin default would stop
   viewers from signing out.
2. **The callback ends with a 200 page, not a 303.** The page carries
   `<meta http-equiv="refresh" content="0;url=/">` and a link.
   - **Why:** the session cookie is `SameSite=Strict`. A 303 at the end of
     the provider's cross-site redirect chain is still cross-site, so
     browsers don't send the new cookie, and the user lands on `/login`
     again.
   - **Why it works:** a refresh from Siphon's own page is same-site.
   - **CSP:** a meta refresh is not a script, so the CSP allows it.
3. **Roles are a struct,** `Roles struct{Admin, Operator, Viewer RoleMatch}`,
   not a map. Strict YAML decoding (`dec.KnownFields(true)`,
   `config.go:544`) and the schema reject other role names, so no extra
   validation code is needed.
4. **OIDC settings are read live,** from `s.Config().Server.OIDC` on each
   request. A changed role mapping applies at the next sign-in.
   - The provider cache is keyed by issuer.
   - The resolved client secret is read from the live config's
     `ClientSecret.Value`.
5. **`siphon explain` is not changed.** `explainKinds`
   (`internal/config/explain.go:40`) has no `server` kind. The schema and
   `docs/tasks/sso.md` document the fields.
6. **No separate config reference doc exists,** so the docs are
   `docs/tasks/sso.md`, the `docs/README.md` row and `llms-full.txt`.

4. **The OIDC flow.**
   - **Where:** a new `internal/web/oidc.go`, registered from
     `portalRoutes`.
   - **`s.oidcProvider(ctx)`:**
     - caches `*oidc.Provider` per issuer under a mutex;
     - the context is `oidc.ClientContext(ctx, source.HTTPClient(o.AllowPrivate, 30*time.Second, 1<<20))`;
     - an error is not cached.
   - **`GET /login/oidc`:**
     - with no OIDC config, answer 404;
     - make `state`, `nonce` and a verifier (`oauth2.GenerateVerifier`);
     - set the `siphon_oidc` cookie,
       `<ts>|<state>|<nonce>|<verifier>|HMAC(key, "oidc:"+…)` (`MaxAge`
       600, `HttpOnly`, `Lax`, `Path=/login/oidc`, `Secure` as
       `secureCookie(r)`);
     - answer 303 to `AuthCodeURL(state, oidc.Nonce(nonce), oauth2.S256ChallengeOption(verifier))`;
     - the redirect URL is `<public_url>/login/oidc/callback`;
     - a discovery failure renders the login page with 502 and
       "SSO provider unreachable: <cleaned error>".
   - **`GET /login/oidc/callback`.** Set `Cache-Control: no-store`, then:
     1. `s.lim.blocked(ip)` means 429;
     2. read and verify the cookie, with an age under 10 minutes on
        `s.Now`;
     3. constant-time compare the `state`;
     4. a provider `error` parameter is a failure;
     5. `Exchange(ctx, code, oauth2.VerifierOption(v))`;
     6. take `id_token` from `Extra`;
     7. `provider.Verifier(&oidc.Config{ClientID, Now: s.Now}).Verify`;
     8. check `tok.Nonce == nonce`;
     9. read the claims into `{Sub, Email string; EmailVerified bool; Name string}`
        plus a raw map for the groups claim (a `[]any` of strings, or one
        string).

     Then map the role with `roleFor(cfg, email, verified, groups)`:
     - emails compare case-insensitively;
     - the highest role wins.

     The outcomes:
     - **No role:** 403 page, audit `oidc_refused` with detail `actor`.
     - **Success:** set the session (12h, `MaxAge` 43200, same attributes
       as the token login), clear `siphon_oidc`, audit `oidc_signin` with
       detail `<actor> as <role>`, and render a 200 "Signed in" page with
       a meta refresh to `/` (decision 2).
     - **Any failure:** `s.lim.fail(ip)`, and 400 with a cleaned message.
       Reuse `mcpoauth`'s `clip`/token redaction idea (copy the small
       regex; don't import across packages for it).
   - **Templates:**
     - **`login.html`:** an "Sign in with SSO" link when OIDC is on, and
       the token form only when `TokenLoginOn()`. The template data
       becomes a small struct `{Err string; SSO, Token bool}`. Update every
       `s.render(w, "login", …)` call.
     - **A new `templates/signedin.html`** for the refresh page and the
       403 and 400 pages.
     - **`layout.html:31`:** show `{{.Actor}} · {{.Role}}` beside Sign out.
   - **`can`:** add `Role string` to `view` and `layout`, set from
     `s.role(r)` in `s.page`, `s.pageStatus` and `s.afterPost`. Add a
     template func `can(have, need string) bool`. Hide with
     `{{if can $.Role "operator"}}`:
     - approve/deny in `approvals.html`, `job.html` and `dashboard.html`;
     - rule toggles in `rules.html`.

     Hide with `can … "admin"`:
     - the edit, new, delete and save controls in `config.html`,
       `logins.html`, `notify.html` and `services.html`;
     - the restore button in the history templates.

     A partial rendered by a direct `s.render` without `Role` hides
     controls, which is acceptable because the server check is the
     guarantee. Check the 11 direct `s.render` sites and set `Role` where
     the view has a request.
   - **Tests** (`internal/web/oidc_test.go`), against an `httptest` provider
     that serves discovery, JWKS (a generated RSA key) and token, and
     signs ID tokens with `go-jose`:
     - the full sign-in for each role, and the highest wins;
     - no match means 403 and an `oidc_refused` row;
     - an `email_verified:false` email doesn't match;
     - each of these is refused and counts toward the limiter: a wrong
       state, a wrong nonce, a wrong `aud`, a wrong `iss`, an expired
       token, a bad signature, and a cookie older than 10 minutes
       (injected clock);
     - the audit row has `oidc:<email>`;
     - `token_login:false` hides the form;
     - the page never contains the code or the id_token.

     The provider is on `127.0.0.1`, so set `allow_private: true` in the
     tests.
   - **Verify:** `go test -race ./internal/web` and
     `TestTemplatesAreCSPClean`.
   - **Traps:**

     - inject the clock;
     - never log tokens;
     - the limiter is shared, so one failing test case must not leave
       others blocked: use a fresh server per case or distinct
       `RemoteAddr`.

## Rollback

- **Revert the merge.** Old-format cookies from this version are rejected
  by the reverted code too, so everyone signs in once again.
- **Remove `server.oidc`** from `siphon.yaml` first. The older version
  rejects the unknown key.
- **No database change,** so there's nothing to migrate back.

## Deviations

- **Step order: 1, 3, 2+4.** `go mod tidy` drops go-oidc while nothing
  imports it, so the dependency (step 2) lands with step 4, its first user.
- **Step 3: a test-only `Options.onNew` hook.** `New` returns only an
  `http.Handler`, so the tests need it to mint role cookies. It's
  unexported, so nothing outside the package can set it.
- **Step 3: `TestPortalPOSTRoles` lists the config verbs itself.**
  `configRoutes` builds `"POST /config/{kind}/{name}/"+verb`, which a
  source scan sees only as a prefix. The test expands it into `check`,
  `save`, `delete` and `reset`, so a new verb needs an edit there too.
- **Step 3, review fix:** `portalAs` first wrote the default role into the
  captured `need`, a data race that also pinned the first request's role.
  It now uses a local copy, and any method other than GET or HEAD needs
  admin by default.
- **Step 4: failure pages are fixed text.** They name the failed step, for
  example "SSO sign-in failed (code exchange)". The cleaned error goes only
  to `slog.Warn`, because exchange and verify errors can carry the
  provider's response body, and the `error` parameter is attacker-chosen
  text. The discovery 502 on the login page still shows the cleaned error.
- **Step 4: failed sign-ins are not audited.** Only `oidc_signin` and
  `oidc_refused` are, so unauthenticated requests can't flood the audit
  table. Every failure still calls `s.lim.fail`.
- **Step 4: the `siphon_oidc` cookie is cleared once `state` matches,** so
  a replayed callback finds nothing.
- **Step 4, review fix:** an unverified email is never the actor. With
  `email_verified` false, the actor is `oidc:<sub>` even when a group
  grants a role. Test: `TestOIDCUnverifiedEmailNotActor`, which fails
  against the old code.
- **Step 2:** go-oidc v3.21.0 and go-jose v4.1.4. go-jose is a direct
  dependency, because the tests sign ID tokens with it. `golang.org/x/oauth2`
  goes from 0.35.0 to 0.36.0. `go mod tidy` changed `vendorHash` once more;
  it's confirmed with `nix build --rebuild .#siphon.goModules`, and
  `nix build .#siphon` passes.
