# Plan: OAuth login for MCP sources

## Approved decisions (from the intent and the spec)

- **Opt-in:** a remote `type: mcp` source opts in with
  `auth: { oauth: { client_id?, client_secret?, scopes? } }`.
  - `client_secret` is an `env:` or `file:` ref, only with `client_id`.
  - `scopes` replaces the discovered scopes.
  - It isn't allowed with `auth.bearer`, an `Authorization` header or a
    `command`.
  - It needs `server.public_url`, which must be https, or http on a
    loopback host.
- **Callback:** `<public_url>/oauth/callback`. It's public, single-use,
  bound to `state`, and expires after 10 minutes. An unknown `state` counts
  toward the per-IP failed-auth limiter.
- **Registration:**
  - dynamic registration by default;
  - pre-registered with `client_id`;
  - a dynamically registered client is reused on re-login (passed as
    `PreregisteredClient` with `Issuer`);
  - no CIMD.
- **Storage:** `credentials/.mcp/<source>/mcp-oauth.json` through
  `cred.Store` (0700/0600, flock, atomic, compare-and-swap `Save`, `.prev`).
  - It holds `resource`, `issuer`, `client_id`, the DCR-issued
    `client_secret` only, `auth_url`, `token_url`, `auth_style`, `scopes`
    and `token`.
  - A login is used only while `resource` equals the source `url` and the
    `client_id` matches the configured one.
- **Manager:** one per daemon, owned by the `job.Pipeline`. There's one
  token source per source.
  - **Steady state:** our own `auth.OAuthHandler`. `Authorize` returns
    `ErrLoginRequired` at once and never waits for a browser.
  - **Login:** go-sdk's `auth.AuthorizationCodeHandler` runs in a goroutine
    with a 10-minute deadline, with `RequestRefreshToken: true`.
  - **Refresh:** on use, through `ReuseTokenSource`, with the result written
    back. `invalid_grant` means login required.
  - **Errors:** cut down to the OAuth `error` and `error_description`.
    Never a token.
  - **HTTP:** discovery, registration, token and refresh requests use the
    source's guarded egress client (the private rules, no redirects).
  - **Pending logins:** in memory only.
- **Agent runs:** only the access token, as an `Authorization` header, and
  masked in the job output. Never the refresh token. No login means the job
  fails with the login message.
- **API (admin token, audited):**
  - `POST /api/sources/{name}/oauth/login` returns `{url}`;
  - `GET /api/sources/{name}/oauth` returns `{status, expiry}`;
  - `DELETE /api/sources/{name}/oauth` logs out.
- **Portal:** status, plus a "Log in" form (CSRF) that answers with a 303 to
  the authorization URL.
- **CLI:** `siphon connect oauth <source> [--no-wait|--logout]`. It polls
  the status every 2 seconds for up to 10 minutes.
- **No new module:** `golang.org/x/oauth2` only loses `// indirect`.

2. **The store and `internal/mcpoauth`.** Done by the coder.
   - **`internal/cred/cred.go:39` `fileProvider`:**
     `"mcp-oauth.json": "mcp"`.
   - **`internal/source/netguard.go`:** export
     `func HTTPClient(allowPrivate bool, timeout time.Duration, maxBody int64) *http.Client { return guardedClient(allowPrivate, timeout, maxBody, false) }`.
   - **New `internal/mcpoauth/mcpoauth.go`:**
     - **`Manager`:**
       - `New(dir string, cfg func() *config.Config, now func() time.Time) *Manager`;
       - `dir` is `<credentials>/.mcp`, used as `cred.Store{Dir: dir}`.
     - **Methods:**
       - `Handler(source) auth.OAuthHandler`;
       - `Token(ctx, source) (string, error)`;
       - `Start(ctx, source) (string, error)`;
       - `Complete(state, code, iss, errParam string) (string, error)`;
       - `Status(source) (status string, expiry time.Time)`, where status
         is `none`, `pending`, `ok` or `expired`;
       - `Logout(source) error`;
       - `var ErrLoginRequired`, wrapped with the source name and the hint
         `siphon connect oauth <source>, or Log in on the Sources page`.
     - **The login goroutine:**
       - a context with a 10-minute deadline;
       - connect with `mcp.NewClient(...).Connect` over a
         `StreamableClientTransport{Endpoint: url, HTTPClient: client, OAuthHandler: h}`;
       - the fetcher parses `state` from the URL, registers it with its
         expiry, sends the URL to `Start` on a channel, and waits for
         `Complete` or the deadline;
       - `NewTokenSource` persists the login and installs a saving token
         source.
     - **`Start`:** waits at most 30 seconds for the URL, and cancels an
       earlier pending login for the same source.
     - **`Complete`:** deletes the pending entry on first lookup.
   - **New `internal/mcpoauth/mcpoauth_test.go`:**
     - **Setup:** an `httptest` authorization server with protected-resource
       and AS metadata (`authorization_response_iss_parameter_supported`),
       `/register` (counted), `/token` (code with PKCE check, and refresh
       with rotation), and an MCP server behind `auth.RequireBearerToken`.
     - **"The browser":** `http.Get` of the authorization URL, whose
       handler answers with the code. The test then calls `Complete`.
     - **Cases:** every Manager item in the spec's Verification section.
   - **Verify:** `go test -race ./internal/mcpoauth ./internal/cred`.
   - **Traps:**
     - inject the clock; no sleeps;
     - pass `oauth2.HTTPClient` in a context, as go-sdk does;
     - no token in `Error()` strings: assert it;
     - `go mod tidy` must move `golang.org/x/oauth2` to direct and nothing
       else.
